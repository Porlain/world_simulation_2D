# Watabou 风格地图优先界面设计

> 状态：设计已确认，实施完成；Menu 已按复核意见改为左侧常驻
>
> 日期：2026-08-03
>
> 适用仓库：`world_simulation_2D`

实施后复核将原右侧临时抽屉调整为左侧常驻菜单；空世界种子每次生成新随机值，功能地标常显名称，道路悬停显示人流、车流和累计出发量。下文保留初始设计记录，以上述复核结果为当前实现准则。

## 1. 结论

1.0 前端从固定三栏操作台改为地图优先界面。城镇地图占满首屏，城镇名称、Menu、比例尺、指北针、图例和时间轴作为地图内叠加界面；生成、模拟控制、图层控制、历史记录和选中对象统计集中到右侧 Menu 抽屉。

底图采用用户提供的 Watabou 参考图所代表的纸张制图风格：灰米色纸面、蓝灰建筑、深炭城墙、浅色街巷和少量红褐标注。此前的深色高科技蓝视觉退出 1.0 主界面。人流、车流和热力继续作为独立的动态叠加层存在。

此次只改变前端布局和渲染表现，不修改 FastAPI 协议、SQLite 数据、模拟引擎、TownSkeleton 或 FlowSnapshot。

## 2. 问题与目标

当前界面把 268 px 控制栏、288 px 统计栏和 82 px 时间轴永久占据在地图四周。地图虽然已具备城墙、街道、建筑、功能地标和流量图层，但视觉上仍像被嵌入仪表盘的图节点视图，与参考图的全屏城镇制图体验明显不一致。

本次必须达到：

- 桌面和移动端第一视口都以城镇地图为主。
- 用户能直接辨认城墙、城门、主街、支路、普通建筑和功能建筑。
- 城镇生成、模拟控制、历史运行和回放功能不减少。
- 人流、车流和热力可分别显隐，关闭后不创建对应 deck.gl 图层。
- 缩放和平移时动态标记继续使用道路世界坐标，不产生屏幕坐标漂移。
- 功能建筑使用与名称对应的地图图案，不再只依赖颜色。

本次不做：

- 不复制 Watabou 源码、字体或图像资源。
- 不新增抽屉、图标或状态管理依赖。
- 不修改 radial-v1 的城镇几何生成算法。
- 不增加昼夜、天气、3D、地形编辑或自定义主题系统。
- 不把图层偏好写入数据库或本地存储。

## 3. 方案选择

| 方案 | 结论 | 原因 |
| --- | --- | --- |
| 地图优先的 Watabou 壳层 | 采用 | 最接近参考，地图占据主视觉，并适合未来世界地图到城镇场景切换 |
| 保留三栏并换肤 | 不采用 | 改动较小，但地图仍被固定面板压缩，无法解决核心空间问题 |
| 地图/分析双模式 | 暂缓 | 多一套布局状态和切换行为，1.0 没有足够收益 |

## 4. 页面结构

```text
┌────────────────────────── 城镇名称 ─────────────────────── Menu ┐
│                                                               │
│                                                               │
│                         全屏城镇地图                         │
│                                                               │
│  比例尺                                图例         指北针    │
├──────────────────────── 时间轴 / 回放 ─────────────────────────┤
```

### 4.1 常驻元素

- 城镇名称在地图顶部居中，使用衬线展示字体；下方只显示生成 seed、人口和运行状态的短读数。
- `Menu` 位于右上角，使用深色小型文字按钮，打开原生 `<dialog>` 形式的右侧抽屉。
- 比例尺位于左下角，根据 deck.gl `viewState.zoom` 计算显示距离。
- 指北针位于右下角。当前 OrthographicView 不开放旋转，因此北向固定向上。
- 图例位于底部靠右，只显示当前启用的图层，不覆盖比例尺或指北针。
- 时间轴贴底并保持全宽，桌面高度 58 px，移动端高度 68 px。

### 4.2 临时元素

- Menu 抽屉宽度为 `min(380px, calc(100vw - 24px))`，从右侧进入；移动端使用全宽。
- 点击地图对象后显示轻量信息条。信息条靠近右侧、位于 Menu 按钮下方；打开 Menu 时统计内容移入抽屉，不同时显示两份。
- 加载、生成失败和渲染错误使用地图顶部的小型状态条，不重新引入固定侧栏。

### 4.3 交互规则

- 原生 `<dialog>` 提供焦点约束和 `Esc` 关闭；点击遮罩关闭。
- 时间轴自动表现实时跟随或历史回放，不增加独立的“实时/回放”模式切换按钮。
- 生成新城镇或选择历史运行后关闭抽屉，让地图立即成为视觉焦点。
- 键盘焦点使用清晰的深红褐轮廓；所有图层开关使用原生 checkbox。


纸张、建筑、道路和城墙构成低饱和底图。流量与选择色只用于动态信息，避免整张地图重新变成蓝色发光界面。

### 5.2 字体

- 城镇名、地图标签：`Georgia, "Songti SC", "STSong", serif`。
- 控制抽屉和读数：现有 `Noto Sans SC Variable` 与等宽数字字体。
- 不新增网络字体请求；离线开源部署保持可用。

### 5.3 地图图层顺序

从底到顶固定为：

1. 纸张方格和城外低对比纹理由 CSS 背景绘制。
2. 地区淡色面。
3. 普通建筑面和建筑边框。
4. 支路、主街和城外道路。
5. 城墙、门楼与城门缺口。
6. 功能建筑图案。
7. 道路热力和地点热力。
8. 人流圆点与车流菱形。
9. 选中对象和必要标签。

道路位于建筑之上，用浅色宽线形成参考图中的街巷留白。热力保持低透明度，不能遮盖道路轮廓。

## 6. 功能建筑图案

图案由现有 deck.gl `PolygonLayer`、`PathLayer` 和 `ScatterplotLayer` 组合，不使用外部图片或新增图标图集。所有图案以 landmark 的世界坐标为锚点，并随地图缩放和平移。

| 类型 | 地图图案 | 识别要点 |
| --- | --- | --- |
| administrative | 方形主体与中央塔楼 | 对称、居中、轮廓端正 |
| market | 中央方块与四向棚顶 | 四向开放，与街道相连 |
| religious | 对称中轴与小型穹顶/十字形平面 | 细长中轴、顶部圆点 |
| military | 厚边界与四角塔 | 最厚轮廓，四角突出 |
| storage | 两到三个并列圆形粮仓 | 重复圆形单元 |
| workshop | 简化锤砧几何印记 | 不对称的横梁和底座 |
| stable | 双排屋顶与中央通道 | 两条平行长体 |
| plaza | 方形空地与中央喷泉/星标 | 留白最大、中心点明确 |
| gate | 城墙缺口与两侧门楼 | 与 wall gap 使用同一坐标 |

普通建筑继续按实际 polygon 绘制。功能图案叠加在对应代表建筑上，而不是用图案替换整栋建筑。

## 7. Menu 抽屉

抽屉使用单列、无嵌套卡片的紧凑布局，顺序固定为：

1. **城镇生成**：generation seed、居民数量、生成按钮、建筑/街道数量与编译状态。
2. **地图图层**：城墙、道路、建筑、功能建筑、人流、车流和热力 checkbox。
3. **模拟控制**：simulation seed、启动/暂停/继续/结束、运行速率。
4. **历史运行**：最近运行列表，显示时间、状态和 tick。
5. **当前选中对象**：地点存量，或道路刚刚出发量、容量和旅行时间。

错误消息紧邻触发它的区域；无法归属时显示在抽屉顶部。禁用状态沿用现有运行约束，不允许在活动运行期间切换场景或生成城镇。

## 8. 前端状态与数据流

```text
App.vue
  ├── 现有 scenario/run/snapshot 状态 ───────────────┐
  ├── menuOpen ───────────────────────► Menu dialog  │
  ├── selectedFeatureId ──────────────► 信息条/抽屉  │
  └── layerVisibility ────────────────► CityMap      │
                                                   ▼
CityMap viewState ─► 比例尺                 townLayers.ts
                                                   │
TownSkeleton ─► 静态纸张地图图层                    │
FlowSnapshot ─► 热力、人流、车流动态图层 ◄─────────┘
```

`layerVisibility` 是一个包含七个布尔值的普通响应式对象。`townLayers.ts` 只在相应值为 true 时返回图层，不创建空层或通用插件注册表。动态 marker 继续直接从连接 path 和 snapshot tick 计算世界坐标。

比例尺监听 deck.gl `onViewStateChange`。缩放值转换为每像素世界单位后，从 `1/2/5 × 10^n` 中选择不超过 140 CSS px 的刻度；标签使用 TownSkeleton 声明的 meter 单位。

## 10. 错误与降级

- bundle 未就绪时显示纸张背景与“正在生成城镇”状态，不显示虚假地图。
- WebGL 失败时保留标题、Menu 和错误条，用户仍可重新生成或选择历史运行。
- 某一动态流量类型缺失时隐藏对应图层和图例，不推断或伪造数据。
- legacy v1 场景继续渲染道路和地点；没有 TownSkeleton 时不伪造建筑、城墙或功能图案。
- `prefers-reduced-motion` 下关闭抽屉滑动和状态脉冲，但保留状态变化。

## 12. 实施与提交顺序

每个模块验证后单独提交并推送：

1. `refactor: make the town map the primary workspace`
   - 全屏布局、标题、Menu dialog、临时统计信息条和紧凑时间轴。
2. `style: adopt parchment town cartography`
   - 纸张底图、蓝灰建筑、浅色道路、深色城墙、标签、比例尺和指北针。
3. `feat: add landmark motifs and layer controls`
   - 九类功能建筑图案、显隐状态、动态图例和抽屉开关。
4. `test: verify map-first simulation workflows`
   - 更新桌面/移动 E2E、视觉截图、README 和第三方声明检查。

提交不得混入当前工作区中与本设计无关的停止脚本或 README 变更。
